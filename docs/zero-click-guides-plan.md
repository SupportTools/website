# Zero-click guide posts: improvement plan

Owner rule: improve, never remove. Nothing on this list gets unpublished, noindexed, deleted, renamed or moved. `url:`, file names, slugs and `date:` stay as they are. CONSOLIDATE rows are suggestions for the owner only and have not been executed.

## Cohort

Posts in the "guide" cohort (1,500+ words with a broad "enterprise / comprehensive / advanced / production" style title and no troubleshooting keyword), published at least 180 days before 2026-10-23, with zero Google clicks between 2025-06-01 and 2026-10-20. Source: `posts.json` and `gsc_page_16m.json` from the prior analysis. The filter returns 106 posts: the 105 from the brief plus `ai-model-serving-tensorflow-seldon-kserve-comparison`, dated 2026-04-26, which sits exactly on the 180-day boundary. It is kept in the table and flagged.

## Data

- Page-level impressions and average position: 16 months, `gsc_page_16m.json`.
- Top queries: a new Search Console pull with dimensions `["page", "query"]`, 2025-06-01 to 2026-10-20, one request per post filtered on the post's path, property `sc-domain:support.tools`.
- Google hides most low-volume queries, so the 106 posts returned only 211 query rows in total; 53 posts have no visible query at all. For those, the class is based on the topic and on what works elsewhere on the site.

What earns clicks on this site is one named tool, product, version, error or procedure per page. Broad "Topic: Subtopic" overviews collect impressions around positions 13 to 15 and convert at about 0.3%. Every proposed title below names one concrete job.

## Classes

- **RETARGET:** Google already shows the page for specific queries. Rewrite title, description and intro to answer that query, add a "Quick answer" section with the exact commands, keep the rest of the page.
- **UPDATE:** facts or versions are out of date. Update in place to current versions, verified against official docs.
- **NEW VERSION:** the post is bound to a version that has moved on. Write a new post for the current version, leave the old post live and unchanged except a "Newer version" banner (the `newer-version` shortcode added on this branch, which renders only once the new post is published), and link the new post back. Only used where the old post is version specific; evergreen tools with a year in the title (xrandr, RACADM, Pi-hole, kubeconfig) are RETARGET or UPDATE in place instead, to avoid two pages competing for one query.
- **NEW ANGLE:** no useful impressions. Rewrite the same topic around one specific, searchable job, keeping the URL.
- **CONSOLIDATE (suggestion only):** near duplicate of another post. If the owner agrees, merge the useful content into the stronger page and add this URL to the target's `aliases:` so it keeps resolving. Not executed.

Effort: **S** about an hour (front matter, quick answer, links, small fixes), **M** half a day (rework several sections and verify versions), **L** a new post or a full rewrite.
